# Blockfield/superbwarfare-fabric bf22

## Кратко

В камере дрона оператор получает зелёную рамку, как и союзники. Сборка и проверки переведены на нативные команды Just для Linux и Windows; Loom закреплён на стабильной версии 1.11.8.

## Для игроков

- Собственный персонаж в камере дрона отмечается зелёным, в том числе без scoreboard-команды на полигоне.
- Союзник по scoreboard-команде остаётся зелёным, противник — белым. Эти три случая отдельно проверены на сохранённом кандидате JAR; ограничения проверки нового релизного артефакта приведены ниже.

## Технические изменения

- `DroneHudOverlay`: зелёный цвет выбирается при `e == player || e.isAlliedTo(player)`, иначе явно устанавливается белый. После каждой рамки цвет снова сбрасывается в белый.
- Проверка исходника bf21 и опубликованного байткода опровергла прежнее предположение о переходе зелёного цвета с союзника на следующего противника: обычный путь уже сбрасывал цвет после `preciseBlit`. Исправление относится к рамке самого оператора.
- Нативные `just setup`, `just check` и `just build` используют кеш проекта и одинаковые команды на Linux и Windows. Добавлены закреплённые lint/format-проверки, CI обеих платформ, массовое форматирование Java/Kotlin и восстановление повреждённого cached venv.
- Gradle запускается с `--no-daemon --max-workers=2` и JVM 2 ГБ; компилятор Kotlin работает в том же процессе. `check` включает проверки headshot/ножа/дистанции ближнего боя и Java lint с `-Werror`.
- Loom `1.11-SNAPSHOT` заменён на `1.11.8`. Официальные checksum JAR и метаданных сверены с локальным кешем; stable JAR побайтно совпадает с использованным cached snapshot, зависимости также совпадают. Gradle wrapper 8.14.2 закреплён checksum.

## Обновлённые компоненты

Игровая версия Superb Warfare остаётся 0.8.9.1 для Minecraft 1.21.1. Изменены собственный overlay и инструменты разработки; новая игровая runtime-зависимость не добавлена. Инструмент сборки Loom закреплён на 1.11.8.

## Совместимость и необходимые действия

Мод имеет `side = "both"` и входит в контракт сборки. Новый JAR нужно одинаково закрепить в клиенте и сервере по URL и SHA512, затем выпустить согласованную пару: сервер первым. Для уже опубликованного bf22 клиентский пин обновляется `scripts/bump-fork.sh superbwarfare bf22`; серверный пин обновляется отдельно. Теги и production Deploy требуют отдельного подтверждения владельца.

## Известные проблемы

Подтверждённой утечки цвета между рамками нет. Отбор целей дрона по видимости, дыму, дистанции и союзности самому дрону этим изменением не меняется: сущность, исключённая до overlay, рамку не получает. Завершённая сборка сама по себе не подтверждает игровую приёмку нового JAR.
